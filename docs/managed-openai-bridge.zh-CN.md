# 本地 OpenAI 桥启动契约（候选，尚未发布）

此候选不修改 streamfix 的 HMAC 通道，不读取供应商密钥，不执行注册数据提供的命令。它只管理使用者显式配置的可选 `openai-bridge` 组件，不是通用本机代理探测器。

## v1 契约

组件由用户配置完成后，原子写入 `HOME/.cccodroid/services/openai-bridge.json`：

```json
{
  "schema": 1,
  "id": "openai-bridge",
  "endpoint": "http://127.0.0.1:34591",
  "runtimeDir": "/absolute/private/runtime",
  "instanceId": "00000000000000000000000000000000"
}
```

- `instanceId` 是安装实例的随机标识，**不是认证密钥**，不得代替本地连接认证。
- 文件不含上游 URL、认证信息、模型或任意命令；上游配置仍由组件自己的管理器处理。
- App 在 `startRun` 中、生成包装地址和启动 CLI 之前，匹配本轮原始 provider 端点。只有 `custom && !login && !local` 且精确的 `http://127.0.0.1:<1024..65535>` 根地址（允许末尾一个 `/`）可以匹配。
- 远端、其他端口、带用户信息/查询串/片段/额外路径/非规范主机写法不会启动组件。不存在或不可解析的注册不让其他接口承担桥的副作用。
- 匹配后必须确认本机组件安装记录 `state=ok` 且拥有固定入口，再调用 Node 执行 `PREFIX/lib/openai-bridge/component.cjs ensure --dir <runtimeDir> --endpoint <endpoint> --instance <instanceId>`。不存在按注册文件执行任意命令的路径。
- 组件必须校验实例、端点和受管清单，启动其单例看护并等待实际健康就绪；成功时标准输出只返回 `{schema:1,id:"openai-bridge",ready:true,endpoint,instanceId}`。失败使用非零退出码。
- App 等待上限 75 秒，失败结束本轮且显示错误，不向模型发送请求。同一实例并发等待共用一次启动操作；一次失败后 60 秒内不反复调用启动器。桥自身也必须有独立、跨启动器调用有效的有限故障恢复预算。
- 停止等待的一个会话不杀死其他会话共用的启动器/看护；本轮不再启动 CLI。生成阶段仍走现有请求取消链。
- 组件管理器卸载时先占住组件操作槽，等待本实例在途启动结束，阻止新的启动，只调用固定组件入口 `uninstall --yes`（不带 purge）。成功停用并移除自身注册后才删除包文件；失败保留组件以便排错/重试。注册残留但安装记录消失时失败关闭，不能执行残留私有运行副本。默认不删除上游配置或用户历史。

## 测试与交付边界

`node scripts/test.mjs managed-bridge` 使用临时 HOME、假组件入口和假注册，验证匹配、等待、并发、失败冷却、取消及卸载边界；这不是最终组件的健康检查，也不是原生 App 或签名包验收。

只有桥组件实现同版契约、归档安装测试和最终签名 App 真机验收完成后，才可承诺交付。现用手工桥与已安装 App 均未修改；不会把旧可解码 URL 测试或预启动的桥作为新版冷启动证据。
