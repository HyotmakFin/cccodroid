# 设计哲学

[English](design-philosophy.md) · **简体中文**

## 为什么做这件事

今天在手机上用 AI 干活，模型要真正"动手"（跑代码、改文件、装依赖、打包），几乎都得把任务送进云端沙箱：一台远方的临时容器，替你执行，再把结果传回来。手机只是一块显示屏。

cccodroid 想证明的是：**这一步不是必须的。**

安卓手机本来就跑在 Linux 内核上，有多核 CPU、十几 GB 内存、几百 GB 存储。只要工具能在这个内核上原生运行，AI 代理就可以直接在你自己的设备上执行：你的文件、你的工具链、你的网络，不经过任何第三方容器。云端只负责模型推理，执行回到本地。

这带来的不只是"能离线写代码"：

- **数据留在本地**：代码和文件不必为了"让 AI 跑一下"而上传到别人的机器。
- **环境是持久的**：装过的包、配置、项目都在，不会随着会话结束被销毁。
- **能触达设备本身**：构建 APK 装回本机、调系统命令、通过 OTG 调试另一台设备，这些是云端沙箱做不到的。
- **成本归零**：执行用的是你已经拥有的算力。

## 这套做法不绑定某一个代理

cccodroid 今天运行的是官方 Claude Code，但底下的方法是通用的：原生工具链 + 系统调用兼容层 + 本地网关 + 图形外壳。任何以命令行形式交付、能在 Linux arm64 上运行的 AI 代理，原则上都能用同样的方式搬到手机上（比如 Codex CLI、Kimi CLI），将来也可能出现官方的移动端版本。

我们乐见这一点。本项目以 Apache-2.0 发布，方法和踩过的坑都公开在仓库里。如果它能让"手机本地执行"成为常态，那正是它存在的意义。

> 公开记录：首个提交与首个版本 v0.1.0 均发布于 2026-10-13。

## 原则

这些原则大多不是事先定好的，而是在真机上一次次撞到问题、一次次定下来的。

### 1. 原版优先，不魔改
Claude Code 从 Anthropic 官方渠道下载，按官方 sha256 清单校验，二进制一个字节都不改；工具链取自 Termux 官方仓库。我们只做让它跑起来的那层：路径前缀改写、系统调用兼容、`apiKeyHelper` 传递密钥。

站在别人的成果上，但不篡改它。这既是工程上的克制，也是对上游条款和用户信任的尊重。

### 2. 贴着平台的原生能力走
不 root、不刷机、不用 chroot / proot / 虚拟机。

- **等长前缀改写**：Termux 的二进制在编译期写死了 `/data/data/com.termux/`。包名 `cc.codroid` 是为此**特意选定**的，和 `com.termux` 一样是 10 个字符，于是逐字节替换就能让所有 RUNPATH、shebang、配置路径直接指对，不需要 `LD_LIBRARY_PATH`、包装脚本或二进制补丁。
- **系统调用兼容**：安卓给应用进程装了系统调用白名单，名单外的调用会被 SIGSYS 杀掉（Android 14 不允许 `epoll_pwait2`）。cccodroid 不放宽这层限制，被禁止的调用依然被禁止；只是把"被禁就杀进程"变成"返回 ENOSYS"，让程序走它本来就有的兼容路径。**安全边界不动，只让失败变得体面。**
- 提权借 [Shizuku](https://shizuku.rikka.app)（可选），后台靠前台服务。

先摸清系统真正允许什么，再在那条边界之内把事做足。

### 3. 以真机实测为准
很多问题只有在实际使用中才会出现：通知在应用退出后仍残留、jlink 报告成功却产出无法启动的镜像、厂商 ROM 冻结后台进程、FUSE 报告过时的文件大小。

我们的做法是先复现，再逐段隔离，最后用证据确认：截图对比、实际切换系统夜间模式、对每个改写过的归档做完整的 CRC 校验。"它说成功了"不算数，"我看到它对了"才算。

### 4. 状态归网关，界面只是视图
生成、排队、中断都由本地网关统一调度，界面只是其中一个视图。断线重连能接上正在跑的那一轮；计时从网关记录的开始时刻算起；界面刷新不会打断生成。

界面随时可以刷新、断开，正在做的事不能丢。

### 5. 精确执行用户的意图
**停止只是停止**：排队中的消息转为暂停，不会被自动发出。**立即发送**是明确的插话，送进正在进行的那一轮，不打断它。

软件不替用户做决定，尤其是不可撤回的决定。

### 6. 任何操作都退得回来
- 语言选项永远以各语言自己的写法显示、不翻译，切错了也认得出怎么切回来；界面脚本出错时会浮出一个不依赖主程序的"切回中文"按钮。
- 工具链更新会保留用户通过 pip / npm -g 安装的内容。
- 更激进的后台保活设置需要用户主动开启。

允许出错，但不让用户被困住。

### 7. 安全是默认值
- 网关只监听 127.0.0.1，每个 `/api/*` 请求都要带上应用私有目录里的 256 位令牌，同时校验 Host 和 Origin。手机上的其他应用和网页驱动不了它。
- 账户登录由 Claude Code 自己完成，cccodroid 不读取、不保存、不转发 claude.ai 凭据。
- 第三方 API 密钥只存在应用私有目录，经 `apiKeyHelper` 传给 claude，不放进环境变量。
- 应用和工具链的更新都先验签名或校验和，再安装。

把手机变成开发机，但不把它变成别人的入口。

### 8. 对外坦诚，可以追溯
- 发布说明中英双语，也会写明不好看的事实，例如"这个修复此前从未进入任何一次工具包构建"。
- 架构图里每个组件都标注了它对应的源码行。
- 每个工具包都附带 SBOM 和带哈希的锁文件；第三方许可证与致谢逐一列出。

公开发布的东西，要经得起别人逐行对照。

## 一句话

> 在不越界、不魔改的前提下，把被低估的安卓手机变成一个可信、可退、真正好用的 AI 代理工作台，让 AI 的执行回到用户自己的设备上。
