## What's new

**Report on GitHub**
- Settings → Troubleshooting has a new **Report on GitHub** button. It opens a new GitHub issue with your device, Android version, vendor system version, chip, self-test results and installed components already filled in; you just describe what went wrong.
- No logs, keys, account details or conversations are included, and you see what will be filled in before the page opens. It needs a GitHub account; without one, **I'm stuck · bundle diagnostics** still works.

**Known issues by phone maker**
- The website's Known issues page has a new section per brand: Xiaomi, OPPO / OnePlus / realme, vivo, Huawei / Honor, Samsung, Pixel, RedMagic / ZTE and Lenovo. It covers how to allow background running on each, and which chips can't use the GPU components.
- Each entry says whether it was tested on a real device or is just the usual path. Only two devices have been tested so far, so if yours misbehaves, please report it.

## Improvements

- With the UI in a language other than Chinese, the descriptions of skills that come with components are now in English too.
- The on-device model download list now comes from the signed component index, so models can be added or removed without an app release.
- Scroll-freeze auto-recovery no longer fires when the content is only slightly taller than the screen, and every recovery is now written to the gateway log to help find the root cause.
- Every component in the extensions page now has a build for the current toolchain (devkit-2026.10.18), and all 17 have been verified on a real device. This fixes cards saying there was no build for your toolchain. If you had a GPU driver installed, tap reinstall when its card asks.
